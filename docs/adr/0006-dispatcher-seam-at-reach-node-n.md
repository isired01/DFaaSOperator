# The Dispatcher seam sits at "reach node N", not at the HTTP call

The original `Dispatcher` was a concrete struct whose five methods took a kubeconfig `secretRef` and remote object names, so nine facts about reaching a node (the Secret naming convention, the remote namespace, the TestRun name, the target-set key, the usability policy) were duplicated across four reconciler files, and nothing could be substituted in a test: the module had no `interface`. The seam moved up: `Dispatcher.Node(env, nodeID)` returns a `Node` handle addressed by LoadTest, and those facts live behind it. The reconciler still decides the runner's environment (`RunnerEnv`: the summary and sync URLs, which depend on the filer addressing it owns); the adapter decides where those values go. Two adapters justify the seam, `k6dispatch.Live` and `k6dispatch/fake.Fleet`, and the LoadTest reconciler is tested through it.

Later amendment: `RunnerEnv` also carries `AssetBase`, injected as `DFAAS_ASSET_BASE`, and every value in it is per generator. The reconciler builds them on the management address detected for that generator (`k6dispatch.GeneratorOf`, from `status.k6Nodes[].managementAddress`) and falls back to the process-wide filer base when there is none, with no asset base ([ADR-0008](0008-detected-management-address-beats-env-fallbacks.md)). The adapter still only decides where the values go.
